# 模型名 ↔ 能力层级映射

判断自身层级、目标层级，或决定确认项里写哪个模型名时读取本文件。**改映射不改协议**：换模型、加模型只编辑本表，`SKILL.md` 的流程、权限和门槛不变。

## 大小写无关匹配（比对逻辑唯一真源）

本表所有模型标识的比对都**大小写无关**。任何一次比较——自读 `<model>` 对第三列、ACK 目标名对第一列——都必须先把两边归一化为小写再比：

```text
if observed.lower() == candidate.lower(): 命中同一行
```

因此 `Sonnet 5` / `sonnet 5` / `SONNET 5`、`claude-opus-5` / `Claude-Opus-5` 均视为同一标识。表格里怎么写不影响匹配，人眼不必逐字校对大小写。第一列展示名仍按用户在模型选择器里看到的原样大小写书写，只是**匹配时**忽略大小写。

## 当前映射

| 用户可见名（写进确认项） | 层级 | `<model>` 已确认标识 | 能力限制 |
| --- | --- | --- | --- |
| Gemini 3.7 Flash | SCOUT | 未确认 | 未确认；默认海量阅读器，单轮失败后仍可再次调用 |
| Terra | SCOUT | `gpt-5.6-terra` | 纯文本；仅用户点名的后备，不写进默认改派 |
| Sol | ANALYST | 未确认 | 纯文本；与 Sonnet 5 同级 |
| Sonnet 5 | ANALYST | `claude-sonnet-5` | 文本+图像输入 |
| Grok 4.6 | ANALYST | `grok-4.6` | 文本+图像输入 |
| Opus 5 | ARCHITECT | `claude-opus-5` | 文本+图像输入 |

**第一列**：用户在模型选择器里看到的名字，原样写进 `ask_followup_question` 的 `question` 与确认项，让用户照着去切换。

**第三列**：同一模型的多个确认标识用顿号分隔，但不同模型各占一行——例如 `claude-opus-4-8` 与 `claude-opus-5` 是不同模型，不因名字相似就并入。"未确认"表示尚未实际观察到该模型在本宿主的标识。首次在某模型下运行时把实读值追加进对应行，不要凭猜测填写，也不要为了消除"身份未自证"就把当前实读串塞进相近的已有行。

**第四列（能力限制）：** 该模型**不具备**的能力，用于判断"按能力交接"（`SKILL.md` 的是否交接表第 1 项）。

- `纯文本` = 只能处理文本，不接受图像/视觉输入。给这类模型派图像分析任务会失败。
- `文本+图像输入` = 可接受图像作为输入（如截图、照片、图表），但不包含图像生成。
- 增补能力时也列在这一列（如 `超长上下文(200K)`、`函数调用`）；未列出默认为标准能力。

**为什么记录"缺什么"而非"有什么"：** 因为标准能力（文本理解、代码、文件编辑）每个模型都有，列出来只是冗余。只记录"会导致任务失败的缺失"，判断规则就是：任务需要某能力 && 该列含该能力 → 按能力交接到具备该能力的模型，不管层级。

未确认的能力限制写 `未确认` —— 第一次在该模型下运行涉及特殊能力的任务时，根据实际成败补齐。例如某模型被派去分析截图，成功 → 该行不含纯文本限制；失败 → 该行标 `纯文本`。

## 自身身份的读取

从 `environment_details` 的 `Current Mode` 块读 `<model>` 值。

## 层级判定

1. 实读标识（小写归一后）与第三列任一已确认标识匹配 → 采用该行层级。
2. 实读标识不在表中 → 按 ANALYST 工作，并在输出中说明实读标识，请用户确认应归入哪一层级。
3. `<model>` 字段缺失 → 身份为 `UNVERIFIED`，按 ANALYST 工作，输出中标注「身份未自证」。

第 2、3 种情况下**不得自称 ARCHITECT**，也不得作出强制升级清单中的决策。宁可多一次交接，不可让未确认层级的模型下架构结论。

## IDENTITY_CHECK 的判定

只比较**当前进程**的 `<model>` 与 ACK 目标行。确认项、`ROUTE_ACK` 文本、用户说「已切换」都不能改 `<model>`。

1. ACK 目标名（第一列或同义简写）与自读标识（第三列）解析到**同一行** → 通过。
2. 解析到**不同行** → `SWITCH_NOT_APPLIED`。拒绝接管，停止；不得再发确认项。
3. 同一条消息明确是「就用当前模型继续，并标注哪些结论未获决策授权」→ 不接管目标行，按当前行层级做完并标注未获授权结论。

匹配大小写无关，写法也不必逐字相同（"Opus 5"与 `claude-opus-5` 视为同一行）。用户说"切到 opus 了"这类简写也按同一行处理，但仍以实读 `<model>` 为准。

Sol 与 Sonnet 5 是**不同行、同一层级**。ACK 写 Sonnet 5 而实读是 Sol（或反过来）→ 仍算 `SWITCH_NOT_APPLIED`，因为选择器上的名字不同；层级相同不等于身份相同。

## 层级顺序

```text
SCOUT < ANALYST < ARCHITECT
```

顺序只用于判断"当前层级是否足以作某项决策"。它不是必须逐级经过的流水线——简单调查可以直接由 SCOUT 完成，高风险问题可以从 ANALYST 直接升到 ARCHITECT。

## 未启用：平台前缀路由（未来触发条件）

当前模型集无同名冲突，暂不引入平台前缀列。**触发条件**：出现两个来自不同平台、用户可见名相同的模型（如 OpenAI 与 Azure 均显示 `gpt-4`）时，才把第三列扩展为 `平台/模型标识` 形式（如 `openai/gpt-4`、`azure/gpt-4`），并让确认项携带带前缀的目标。未命中该条件前不加列，避免过度设计。
